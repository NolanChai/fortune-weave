# Fire Emblem Fortune's Weave Wiki

A static Astro wiki with Bird Time dialogue and a character panel prototype.

- Site: [www.nolanchai.dev/fortune-weave](https://www.nolanchai.dev/fortune-weave/)
- Repository: [NolanChai/fortune-weave](https://github.com/NolanChai/fortune-weave)

## Development

Use Node.js 24 and npm:

```sh
npm ci
npm run dev
```

Open the local URL printed by Astro, including `/fortune-weave/`. To check and build the production site:

```sh
npm run build
npm run preview
```

The build validates the character mappings, class requirements, source references, and asset checksums, checks Astro and TypeScript, then produces static HTML in `dist/`. Page data is included in the initial HTML; JavaScript adds search, filters, and character panel navigation.

The main navigation contains Characters (`src/pages/characters/index.astro`), Bird Time (`src/pages/index.astro`), and Gifts (`src/pages/gifts.astro`). Shared navigation and page metadata live in `src/layouts/SiteLayout.astro`. Styles are in `src/styles/`, with one file for the shared design and one per page. Browser interactions live in `src/scripts/`. Edit the canonical data and assets in the folders below. `public/` is generated by the development and build commands, so do not edit it directly.

## Gifts

`/fortune-weave/gifts/` has a searchable portrait picker that lets you select multiple characters. **Show characters** applies the selection and displays their gift panels side by side on desktop, stacked on mobile. Closing the modal or pressing Escape discards pending changes. The selection is shareable through `?characters=peter,tialla,guzran`; existing `?character=guzran` links still work. Gift search filters every selected panel. Portrait links jump to each character's panel.

The **My inventory** view has quantities and matching recipients. Inventory stays in this browser's local storage; the page does not upload it or mark gifts as given. Recipients sort by the number of distinct loved gifts you own, then really liked gifts, then name. Quantities show what you own, not an allocation across recipients. Without JavaScript, all character preference lists remain readable.

`data/gifts.json` is the canonical snapshot, checked September 21, 2026: 87 gift names, 53 characters, and 253 explicit preferences covering 38 characters. Names come from [Game8's item catalog](https://game8.co/games/Fire-Emblem-Fortunes-Weave/archives/621281#hm_3); relationships preserve the **Loved Gifts** and **Really Liked Gifts** tiers in its [gift guide](https://game8.co/games/Fire-Emblem-Fortunes-Weave/archives/623690#hl_1). Only names and explicit relationships are imported, not item descriptions or inferred preferences from general interests. Each record references its source. Missing relationships are unknown, not neutral or disliked; Cai currently has no documented item preferences in this source.

The catalog includes 80 distinct names after treating “Candly Crystals” as a probable spelling variant of “Candy Crystals.” The original spelling remains a searchable alias, with the unresolved in-game spelling noted in the data and page. Seven more gift names come from the preference guide. These guide snapshots are incomplete and have not been independently verified in-game.

`scripts/prepare-gifts.mjs` validates IDs, source references, tier labels, duplicate pairs, and coverage before the build. It generates `public/data/gifts.csv` and `public/data/gift-preferences.csv` from the JSON; both CSVs and the JSON are downloadable under **Sources & data**. Edit the JSON and rebuild to refresh every export. Run `node --test scripts/gift-inventory.test.mjs` to check saved-data handling, quantity bounds, and representative source records.

The gift icon uses a CSS viewport into the unchanged user-supplied `assets/gifts/reference-menu.png` (811 × 914). The surrounding panel, rules, and typography are HTML/CSS. No inventory quantities are imported from the design reference.

The picker reuses the existing 48 character icons. Five additional portraits (Eshmel, Hong Hua, Troy, Gaitz, and Noctula) come from Game8's gift guide and are stored unchanged in `assets/gifts/characters/`. `assets/gifts/index.json` records source URLs, dimensions, and checksums; the build requires a portrait for every character in the gift database.

The shared theme uses deep green backgrounds, cream type, and muted gold rules. Bird Time keeps all character rows and its existing search, with framed sections matching the character pages. Characters with imported profiles link to them from Bird Time.

## Character profiles

Open `/fortune-weave/characters/` and select Cai, Peter, Tialla, Guzran, or Ultand. Profiles follow the user-supplied green-and-gold references: Stats, C.Arts/Magic, Class, and Personal History. Cai also has a Unique Abilities view. Arrows cycle through the available views; the diamonds select them directly. The tab list also supports Left/Right and Home/End. URL fragments preserve the selected view on reload. Narrow screens stack the columns and scroll the class grid within the panel. The experience bar and “Next” readout are omitted for every character.

The **All information** switch opens a continuous page containing every section. Use `/fortune-weave/characters/cai/?view=all` to link directly to that layout. Section links work within the scrollable view, and the layout survives reloads. Repeated identity cards and empty decorative rows are omitted in this view; the original Panels layout remains available.

`data/characters/{id}.json` contains each character's text and values transcribed from the references. The panels show **save-state values** at each capture's displayed level, not universal base stats or growth rates. The Class view reproduces the pictured icons without inferring additional class names, requirements, or availability. Peter has Curved Shot and Vital Shot; Tialla has Lend Strength, Fire, and Heal, with two pictured flier specialties. No Unique Abilities are inferred for Peter or Tialla from missing captures.

Ultand's four captures show a level 7 Diviner with Patch Up, Fire, Heal, and the Temple Army banner. Her inventory, equipped abilities, and combat arts are empty. `capturedClassIcons` limits her class grid to the pictured Commoner and Diviner; the other profiles retain their existing grids. Her age remains 22 as captured. Her nine personal growth rates come from Serenes Forest; no starting stats were available on her Fire Emblem Wiki page (revision 771632, checked September 21). Bishop and Ovate recommendations use sourced class mechanics, with Warrior as an explicitly untested physical-support experiment.

`src/data/characters.ts` registers the profiles used by the roster, Bird Time links, and static `src/pages/characters/[id].astro` routes. `CharacterPage.astro` and `CharacterIdentity.astro` share the layout while rendering each profile's own stats, inventory, abilities, class icons, and history. The build validates profile IDs, basic stats, item durability, art costs, and required PNG captures.

The separate `referenceStats` records for Cai, Peter, and Tialla contain reported **level 1 Commoner** stats from Fire Emblem Wiki ([Cai](https://fireemblemwiki.org/wiki/Cai#Starting_stats_and_growth_rates), [Peter](https://fireemblemwiki.org/wiki/Peter#Starting_stats_and_growth_rates), [Tialla](https://fireemblemwiki.org/wiki/Tialla#Starting_stats_and_growth_rates)), plus nine personal growth rates from [Serenes Forest](https://serenesforest.net/fortunes-weave/characters/growth-rates/). All nine growth rates for each character agree between those sources. Cai has Movement 4 plus 1 from Brio; Peter and Tialla have Movement 4. Peter's reported starting Build is 1, separate from Build 2 in the supplied level 5 capture. Sources, scope, and the check date (21 September 2026) are stored with the data. These community references are still being completed; the starting values have not been independently verified in-game. Class modifiers, stat caps, and Cai's separate level 45 NPC version are not folded into these records.

`CharacterReferenceStats.astro` renders the starting-stat and growth table below either layout when a profile includes that record, with direct source links. Rates of 45% or higher use bold gold, with a visible legend. The same threshold applies to growth values in the class recommendations and is defined by `HIGH_GROWTH_RATE` in `src/data/characters.ts`. The build checks that the reference has the complete nine-stat set and valid numeric ranges.

`data/character-builds.json` contains three class recommendations per character: a recommended role, an alternative, and an untested theorycraft build. `CharacterRecommendations.astro` renders them below the growth table in both layouts, with an All information section link. The routes are our synthesis of [Siliconera's role guidance](https://www.siliconera.com/which-fire-emblem-fortunes-weave-main-character-route-should-i-play-first/), its [character guide](https://www.siliconera.com/who-are-the-best-fire-emblem-fortunes-weave-characters/), growths, and class mechanics. They are not published optimal-build rankings or fixed promotion trees.

Class paths reference IDs in `data/classes.json`, so final exam targets, licenses, renown, and Cai-route unlock conditions come from the existing class records. Each recommendation includes its rationale, tradeoff, and source links. Personal growth highlights come from the profile rather than a second copy of the rates. The Ovate examples add [Fire Emblem Wiki's reported class modifiers](https://fireemblemwiki.org/wiki/Ovate#Growth_rate_modifiers) to personal growths; missing class modifiers are never assumed to be zero. The build validates profile/class/source references and requires sourced modifiers for every displayed combined rate.

Ability interactions are deliberately specific: Steady Aim extends bow combat arts; Tactician's Wit extends combat arts usable on allies, not healing spells. Cai's magic experiment does not assume additional Blaze scaling, and Tialla's mounted support experiment does not assume extra Song of Courage range.

The 21 original PNG captures live in `assets/characters/{id}/reference-*.png`. `CharacterGraphic.astro` uses CSS viewports into each character's unchanged files for portraits, sprites, item icons, the banner, and Cai's Red Jewel. The shell, typography, tables, and panel navigation are HTML/CSS/SVG. Capture coordinates use the 2048 × 1152 reference scale, with aspect-ratio adjustments for Tialla's history and Ultand's arts captures. Background sizing scales proportionally to the full-resolution originals. This prototype keeps the source images intact (about 95 MiB); individual game-art exports can replace them later without changing the panel layout. Frame decorations are decorative; source screenshots' performance and OS overlays are not displayed.

The existing Classes research remains at `/fortune-weave/classes/`, unlinked from the main navigation. Its labels now use “Unlock conditions.” The current character prototype does not add a full class database to Cai's page.

## Classes

`data/classes.json` records 35 Beginner, Specialty, and Advanced classes, with 34 reported skill-rank sets, mastery names and effects, route unlocks, restrictions, and per-record sources. `checkedAt` records the research date. Skill ranks are certification targets, not minimum base stats, guaranteed pass rates, or complete weapon-access lists.

The page has an overview of tier access, a filterable class table, certification guidance, a growth-rate example, and separate disclosures for later tiers and source coverage. The game allows certification between class lines, so the page deliberately does not imply fixed promotion edges.

Coverage is incomplete: War Monk's ranks and mastery, the complete Master/Divine rosters, and full class base-stat/growth tables remain unverified. Elephant Rider's rank and mastery have one guide source. Source notes preserve discrepancies, including Blacksmith's unlock and the Caladrius/Caldarius spelling. Bardinger's Spear B agrees with Polygon and the original Direct screenshot despite a C in another guide. Unknown values remain null.

The original Nintendo mount artwork and growth-rate screenshot, plus a Direct certification screenshot hosted by Serenes Forest, are in `assets/classes/`. `index.json` records source URLs, dimensions, credits, byte counts, and checksums. No class sprites from other Fire Emblem games are used as substitutes.

Research sources and scope are embedded in the data and listed in the Classes page. Nintendo supplies the system explanation and original artwork; Polygon supplies most rank and route records; Pocket Tactics, All Things How, Fdaytalk, and Serenes Forest provide cross-checks and additional coverage. Guide reports are not presented as independent in-game verification.

## Deployment

Push to `main` to run [Deploy to GitHub Pages](https://github.com/NolanChai/fortune-weave/actions/workflows/deploy.yml). The workflow builds with the committed npm lockfile and publishes `dist/` through GitHub Actions. It can also be run manually from the Actions tab.

Pages uses **GitHub Actions** as its build source. No separate hosting service or deployment secret is required. If the repository name or domain changes, update `site` and `base` in `astro.config.mjs`.

The account's existing GitHub Pages domain is `www.nolanchai.dev`. GitHub automatically redirects `nolanchai.github.io/fortune-weave/` to `www.nolanchai.dev/fortune-weave/`.

Deployment follows Astro's [GitHub Pages instructions](https://docs.astro.build/en/guides/deploy/github/).

## Character assets

48 character icons from Polygon's [Bird Time guide](https://www.polygon.com/fire-emblem-fortunes-weave-bird-time-correct-answers/), organized for a static character database. Each icon is an original, unchanged 226 × 226 JPEG downloaded from the article's image links. The images total about 512 KiB.

```text
assets/
  characters/
    index.json
    alexandra/
      icon.jpg
    benditz/
      icon.jpg
    ...
    sha-lan/
      icon.jpg
    yang-jie/
      icon.jpg
```

Folder names are lowercase character IDs, with hyphens between words. Display names retain the article's spelling and spacing, such as `Sha Lan` and `Yang Jie`. Characters are matched to their article headings, including when the original image filename does not contain their name.

## Database index

[`assets/characters/index.json`](assets/characters/index.json) contains:

- `schemaVersion`: the index format version, currently `1`.
- `source`: the article URL, publisher, title, and retrieval time in UTC.
- `characters`: alphabetically ordered records with `id`, `name`, `icon`, dimensions, MIME type, byte count, SHA-256 checksum, original image URL, and article section anchor.
- `missingCharacters`: known gaps in this source. The article explicitly omits **Gaitz** and supplies no icon for him.

Every `icon` path is relative to the index file. `sourceSection` is an anchor within `source.url`. Coverage reflects this article, not an independently verified full game roster.

## Asset URLs

The original assets and JSON are copied unchanged into the published site. From an HTML page at the site's root, load the index and resolve its image paths like this:

```js
const indexUrl = new URL("./assets/characters/index.json", document.baseURI);
const response = await fetch(indexUrl);
if (!response.ok) throw new Error(`Character index failed: ${response.status}`);
const database = await response.json();

const characters = database.characters.map((character) => ({
  ...character,
  iconUrl: new URL(character.icon, indexUrl).href,
}));
```

Resolving paths this way preserves a GitHub Pages project prefix such as `/fortune-weave/`. For a direct image in a root HTML page:

```html
<img src="./assets/characters/alexandra/icon.jpg"
     alt="Alexandra" width="226" height="226">
```

The site can serve these local copies without contacting Polygon. Original image URLs remain in the index for attribution and traceability.

## Bird Time

[`data/bird-time.json`](data/bird-time.json) contains 465 dialogue quotes and 464 answers across the same 48 character IDs. Join each record's `id` with the character asset index to find its portrait.

Each character has an `entries` array. An entry contains a stable ID, the exact dialogue quote in `topic`, the response choice in `answer`, and its one-based `sourceRow` in the character's article table. `sourceQuestionSha256` verifies the source quote after whitespace normalization.

The data preserves the article's coverage: some characters have fewer than ten listed prompts, Gaitz is absent, and Seteth's fifth answer is blank. That answer is `null`, with an explanatory `note`. Do not treat it as a correct empty response or invent a replacement.

Four answers had inconsistent capitalization or terminal periods. Their display labels are normalized, and the original values are retained in `sourceAnswer`. Source URLs and retrieval time are stored in the data rather than displayed in the page header or footer.
